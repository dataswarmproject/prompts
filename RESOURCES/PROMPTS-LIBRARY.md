## Development & Technical

### Act as an Ethereum Developer
**Use Case**: Blockchain development, smart contracts

**Prompt**:
```
Imagine you are an experienced Ethereum developer tasked with creating a smart contract for a blockchain messenger. The smart contract should have functions to send messages (both user-to-user and user-to-group), keep track of all messages sent, and allow users to retrieve their message history. Provide the Solidity code for this smart contract.
```

## System Prompts for Popular AI Tools

### ChatGPT (GPT-4.5/4o)
**Context**: OpenAI's integrated assistant with embedded tool schemas

**Key Elements**:
- Identity: "You are ChatGPT, a large language model trained by OpenAI, based on the GPT-4.5 architecture"
- Knowledge cutoff and current date inclusion
- Inline tool schemas (dalle, python, web, bio)
- Extensive safety policies
- Tone adaptation: "adapt to the user's tone and preference"

### Claude (Anthropic)
**Context**: Helpful, harmless, honest assistant

**Key Elements**:
- Identity: "The assistant is Claude, created by Anthropic"
- Persona focus on being helpful and wise
- Safety constraints on graphic content
- Conciseness directive: "provides the shortest answer it can"
- Professional tone with kindness

### Vercel v0
**Context**: UI component and Next.js application generator

**Key Elements**:
- Identity: "You are v0, Vercel's AI-powered assistant"
- Framework specificity: shadcn/ui, Tailwind CSS, Next.js App Router
- Planning phase: mandated `<Thinking>` tags before code generation
- MDX components as tools
- Refusal approach: "MUST NOT apologize or provide an explanation"

### Claude Code
**Context**: Code modification system with style adherence

**Key Elements**:
- Style consistency: "understand the file's code conventions... follow existing patterns"
- Comment restriction: "DO NOT ADD ***ANY*** COMMENTS unless asked"
- Modular approach to code changes
- Context management for long-running tasks
- Professional objectivity in responses

### Cursor
**Context**: AI code editor

**Key Elements**:
- Direct communication mandate
- Forbidden conversational starters: "STRICTLY FORBIDDEN from starting with 'Great', 'Certainly', 'Okay'"
- Tool definitions with parameters
- System information inclusion (OS, shell, directories)

## Best Practices

### Do's
- **Be Specific**: Provide clear context and requirements
- **Set Constraints**: Define what you want and don't want
- **Use Examples**: Show the AI what you're looking for
- **Iterate**: Refine your prompts based on results
- **Save Winners**: Keep a library of prompts that work well

### Don'ts
- **Avoid Ambiguity**: Vague prompts lead to vague results
- **Don't Overload**: Keep prompts focused on one task
- **Skip Assumptions**: Explicitly state your requirements
- **Ignore Context**: Provide relevant background information
- **Forget Formatting**: Use clear structure and formatting
